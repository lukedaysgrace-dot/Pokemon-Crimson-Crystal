# Crimson Crystal: fourth sweep (bugs and errors), 2026-10-31

No dialogue was changed, and Proton's lines are untouched. This sweep found no
new dialogue problems.

## Game fixes

### 1. Free ROM0 space could overwrite the cartridge header (crash on boot)
`home.asm` defined the `Header` section as only `nop / jp _Start` (4 bytes), so
the linker treated `$0104–$014F` as free space. rgbfix then writes the Nintendo
logo and header over that range. Right now nothing is placed there, but your
fixed-bank code is almost full. Grow a small routine such as the VBlank
scheduler or the Cerulean Cave hook by a few bytes and it lands in that gap. The
ROM then builds with no error and crashes when it boots. I hit exactly that
while testing.

**Fix:** the section now reserves the whole header area
(`ds $0150 - $0104, $00`), as pret does. The ROM is byte-identical, but the
build now stops with an error instead of producing a broken ROM.

> Heads-up: ROM0 is nearly full. The release ROM has about 35 free bytes and
> the debug ROM has less. Put new home-bank code in a ROMX bank where you can.

### 2. Sprites could glitch for a frame when scrolling, palette changes and tile animation coincide
At CGB double speed, `VBlank0_Graphics` can do three things in one VBlank: a
full scrolling update (20 tiles), a palette upload and a tileset animation
frame. When all three happen together, the OAM (sprite) upload ends after VBlank
has finished, on line 0 of the next frame. Your own
`tools/test_engine_optimizations.py` caught this ("Tileset0 … OAM [0]").

**Fix** (`engine/tilesets/tileset_anims.asm`): at double speed, if VBlank is
already past line 148, the tile animation waits one frame. Normal speed is
unchanged. `test_engine_optimizations.py` now passes all 10,107 checks on both
ROMs, and the overworld, weather and surf tests still pass.

### 3. BRIGHTPOWDER: undid my change from last round
Last round I added BRIGHTPOWDER to the Mahogany held-items counter and raised
its price from 10 to 2000. That was wrong. Your item catalog test makes it
**trainer-theft only** on purpose: Koga and Janine hold it. 10 is also the
vanilla price. I've put the mart (11 items) and the price back to how you had
them.

## Test tools brought up to date (no game changes)
These failures came from the tests, not from the game:
- **16-bit item rows** (`wItems` rows are now 3 bytes) and the moved save/WRAM
  addresses. These affected about 25 tests: the Archer, Buena, Celadon,
  Anthony, Rooftop, Olivine, Kiyo, Cycling Gang, Tower UI, story, Wishing Star,
  fishing and contest tests, the decoration shops, Ecruteak, apricorns,
  overworld state and League progression.
- **Hidden items** are 4 bytes (`dw flag, dw item`). `test_apricorn_trees`
  only read 3.
- **Mahogany shop test:** the prices for items 11 and up are in
  `wMartExtraPrices`, and the test now includes WIDE LENS.
- **Wishing Star test:** the meteor is now a solid boulder, so the test
  approaches it from the rim beside it.
- **Animation "dropped object" checks** (Psyshock, Fiery Dance, Infernal
  Parade, Octazooka, Sacred Fire): the game's queue count matches the source
  exactly. The emulator's hook sometimes reports one object twice when an
  interrupt lands on it. The tests now count only real drops, and the Sacred
  Fire test ignores the duplicate.
- **Selfdestruct test:** when the user faints, HIDE_MON is supposed to leave its
  sprite cleared. The test no longer treats that as a leak.
- **Trainer sprite test:** HOSTESS has no trainers yet, so its placeholder intro
  text is skipped. Its graphics and palette are still checked.
- Smaller stale expectations: Pidgeot's revamped stats, Kiyo's slot-2 moves,
  Girafarig's Wish source, the HOSTESS class index and save version 5.
