# Smooth Palette Fades Port (from Polished Crystal / Polished Coral)

Status: implemented 2026-08-02. Built with rgbds 0.5.2 and emulator-tested
in SameBoy (CGB-E): intro/title/menu fades verified frame-by-frame — 16
even brightness steps instead of vanilla's 3-4 jumps, at vanilla pacing.

## What it does
Replaces the vanilla 4-shade "palette rotation" fades (the chunky
white/purple/orange flashes) with Polished Crystal's color fade engine:
every RGB channel of all 16 palettes is interpolated toward its
destination a little each frame. Covers all screen transitions that go
through the standard fade functions: opening/closing menus (Pack, Pokedex,
Pokegear, Trainer Card, save, etc. via `FadeToMenu`/`FinishExitMenu`),
warps and map transitions, the title/intro/Oak sequence, Hall of Fame,
link rooms, time-set screen, whiteouts, and every map script that calls
the `FadeOutPalettes`/`FadeInPalettes`/`FadeBlackQuickly`/`FadeInQuickly`/
`BattleTowerFade` specials.

## How it works
- `engine/gfx/fade.asm` (new, floating ROMX section "Smooth Palette Fades"):
  `_DoFadePalettes` fades the active palettes (`wBGPals2`/`wOBPals2`)
  toward a destination over up to 31 steps, uploading each step via
  `hCGBPalUpdate`. Destination is selected by `hPalFadeMode`:
  `PALFADE_BOTH/BG/OBJ` fade toward `wBGPals1`/`wOBPals1`;
  `PALFADE_TO_BLACK`/`PALFADE_TO_WHITE` fade to solid black/white while
  leaving `wBGPals1` untouched (so a later fade-in still has its target —
  vanilla's rotation fades never modified the loaded palettes either);
  `PALFADE_FLASH` fades to black and back.
- `home/fade.asm`: small wrappers (`FadePalettes`, `FadeToBlackPals`,
  `FadeToWhitePals`). The four `Rotate*Palettes*` functions now use the
  smooth engine on CGB; the DMG table code is kept for completeness.
- `engine/tilesets/timeofday_pals.asm`: the five fade specials use the
  smooth engine on CGB. Fade-ins end with `farcall ApplyWeatherTint` +
  `hCGBPalUpdate`, because the fade lands on the untinted `wBGPals1`
  colors (no-op unless overcast/rain/thunderstorm is active).
- `data/fade_step_amounts.asm` (new, 1KB table): Polished computes each
  channel's per-step movement with `SimpleDivide` loops, which is fine at
  their always-double-speed CGB but costs ~2 frames per step at our single
  speed. The same arithmetic is precomputed into a
  `[steps remaining][distance]` table (generated by replicating
  `FadeColorStep`'s math; every channel still lands exactly on target).
- Every step is fully computed before `hCGBPalUpdate` is raised, so the
  screen only ever shows clean, complete steps (uploading mid-computation
  causes a shimmering/torn look on detailed screens like the overworld).
  `FadeDelay` then holds each step to a fixed length - exactly 2 frames
  (or `Delay/steps` if larger) measured from the step's start via
  `hVBlankCounter` - because uneven step timing reads as stutter. If the
  active VBlank routine doesn't tick `hVBlankCounter` (only VBlank0/6 do),
  it falls back to simple frame delays instead of waiting forever.
- RAM: `hPalFadeMode` (hram, $ffec), `wPalFadeDelayFrames`/`wPalFadeDelay`
  (must stay adjacent, in that order)/`wPalFadeFrameStamp` taken from the
  `ds 106` padding in the "GBC Video" WRAMX section.
- Constants: `PALFADE_*` in `constants/gfx_constants.asm`.

## Durations (`c` = step count; each step lasts 2 frames)
Updated 2026-08-02: step counts halved so total fade time matches Polished
Crystal (Polished's menu/warp fades run ~10 frames total; ours previously
ran 12-20). A full fade step's math takes most of a frame at single speed,
so the 2-frame cadence is the fastest even pacing available - fewer, evenly
paced steps is how the totals come down.
- `FadeOutPalettes`/`FadeInPalettes` (menus, warps): 5 (10 frames total)
- `FadeInQuickly`/`FadeBlackQuickly`: 4 (8 frames)
- `BattleTowerFade`: 8 (16 frames; deliberately the slow one)
- `RotateFourPalettesRight/Left` (intro, timeset — black fades): 5 (10 frames)
- `RotateThreePalettesRight/Left` (intro, HoF, link — white fades): 4 (8 frames)

Tune these `ld c, N` values to taste; total = 2N frames, N color steps.

## Not covered / possible follow-ups
- Battle transition flash still uses its own BGP code (untouched).
- The Crystal splash movie's palette cycling is untouched.
- Polished's gradual overworld fade while walking between map connections
  (`OWFadePalettesStep` hooked into the overworld loop) was not ported.
- Under active rain/overcast, fade-ins land on untinted colors for one
  frame before the tint reapplies (imperceptible in practice); pre-tinting
  the fade target would need a scratch palette buffer.
